# Native admission, no-fee profile

`validate(&NoFeeAction)` accepts borrowed account bytes so the same validation can run in Anchor queue admission and the native settlement guard. It checks the three ZK-program-owned preverified contexts with upstream proof extraction, all encryption-key relationships, present source funding, destination capacity and ciphertext arithmetic, exact native instruction variant/offsets/auditor ciphertexts, configured hook, source authority, expected amount commitment and source successor.

The strict initial extension allowlist is mint `ConfidentialTransferMint` + `TransferHook`, and token account `ConfidentialTransferAccount` + `TransferHookAccount`, optionally `ImmutableOwner`. Both required extensions must exist. Every other extension is rejected, including transfer fees at zero bps, CPI Guard even when disabled, memo requirements and paused/nontransferable profiles. Accounts must be distinct, initialized, unfrozen and nonnative, without delegates. Hook transferring flags must be clear. This intentionally narrower profile avoids approximating native behavior for extensions the demo does not support.

The owner authority must be an ordinary system-owned, zero-data signing wallet. Token-owned multisig accounts are excluded even when marked signer, because the native processor applies separate multisig authority rules. The caller supplies real account ownership/data and authenticated signature flags, validates hook metadata routing, binds source/prepared action/proof bytes, and enforces Job/permit, expiry, administrator authorization and consumer semantics. This crate neither creates permits nor queues computation. Queue validation is a present-state check: later source/recipient changes can still prevent commit. Keep native execution and settlement checks.

The client AES decryptable balance cannot be authenticated without the account-wide client secret; its exact bytes remain owner-authorized and action-bound, while native funding uses the independently proved ElGamal ciphertext. Never send reusable keys to admission/MPC to validate this auxiliary balance.

Run `cargo test --locked --offline --manifest-path crates/native-admission/Cargo.toml`. The twelve test groups first reverify six archived genuine proofs with SDK 7.0.1, then exercise valid actions, individually valid mixed proof sets, funding/account/key/instruction mismatches, unsupported extensions and recipient failures. Fixtures contain only public account/proof material and source hashes. These are host tests with scaffolded account ownership and signer flags; they are not fresh validator, signature, MPC, or settlement evidence. See `UPSTREAM.md` for arithmetic provenance.
