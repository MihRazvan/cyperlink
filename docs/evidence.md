The custom-policy runs bind all four encrypted successor slots, source native state,
consumer and release/schema/domain. The two-node runtime is real local distributed
computation on one host/operator setup. Offline reviews verify retained signatures,
account relationships and artifact correspondence; they are not independent BLS
verification, historical consensus proofs or production security audits.

Synthetic allowance, amounts and inferred remainders in test reports are labeled
**test-observer disclosures**, not private balances exposed by the application.
Host fixtures, signed simulations, landed rejection transactions and live callbacks
must stay separately identified. Ten matching ELFs in a run do not qualify later
source changes without a new actual loaded-byte check.

## Recovery evidence and limits

In v23b, receipt HTTP503 still allowed a committed bound account observation. Combined
receipt/status/account outage yielded unresolved. Restored RPC returned null because
history was pruned: delivery remained expired-unresolved while the paid effect stayed
committed. No cached receipt was injected as live. The later Console v2 run captured
actual original-receipt restoration on a fresh useful payment before pruning; this
does not change the historical v23b result. The license
in that run is now expired (`licenseActive: false`); historical payment does not renew
access or authorize another charge.

Console v2 used a separate process with no signer flags. Receipt HTTP503 yielded
`observed-without-receipt` with a committed effect; adding account HTTP503 left current
observation unavailable while preserving the historical paid fact. Restored RPC returned
the same landed signature and wire hash. All six tracked accounts and 75 immutable
signed/attempt/simulation files were unchanged, with no simulate/send RPC calls.
This is controlled local fault coverage, not arbitrary crash/provisioning recovery.

The Console browser archive has four policy decisions and two paid effects on the
retained local ledger. Its offline verifier checks exact owner/admin messages, native
amount commitment in callback output, nonce advancement without query payment, full
encrypted settlement successor and exact merchant/license terms. It does not separately
verify BLS or historical consensus. Startup matched ten actual loaded ELF files; no
program or circuit source changed for Console. The report separates query, callback
and settlement costs and excludes native preparation/deployment costs.

Failed Console harness runs remain under `.local/`: early hidden-element selectors,
an exposed superseded-history issue subsequently fixed, an unrecognized generic fault
that correctly propagated instead of being treated as HTTP503, and an incorrect visual
test assumption that a still-active license had expired. None is counted as a pass.

The first v23 harness failed because its read-only RPC allowlist omitted blockhash
queries. Corrected v23b permits those reads and records pruning honestly. Other failed
and intermediate runs—including expiry1101, source-prestate701 and delivery diagnostics—
remain preserved. They are not silently counted as successful executions.

## Reproduce relevant checks

Use the [pinned setup](local-bootstrap.md). Choose fresh outputs; never reset a
reference ledger or overwrite a failed attempt.

```sh
# Host SDK and exact-transaction recovery checks; no distributed execution claim.
node --test packages/local-client/test/*.test.mjs packages/policy-client/test/*.test.mjs packages/sdk/test/*.test.mjs

# Real session crash/payment qualification on a freshly deployed license instance.
node examples/license-session/qualify.mjs .local/INSTANCE/instance.json .local/NEW-SESSION-RUN
node examples/license-session/verify.mjs \
  --results .local/NEW-SESSION-RUN/results.json --instance .local/INSTANCE/instance.json \
  --output .local/NEW-SESSION-RUN/review.json \
  --corruption-output .local/NEW-SESSION-RUN/corruptions.json

# Read-only live recovery of an existing paid operation; test-only HTTP faults.
node examples/license-session/receipt-outage.mjs --qualify \
  .local/INSTANCE/instance.json .local/PAID-OPERATION .local/NEW-OUTAGE-RUN
```

The license harness expects its documented reference policy/initial state; do not
apply it blindly to arbitrary merchant/customer policies. The [direct client](../examples/license-direct/README.md)
and [authoring guide](custom-policy-authoring.md) describe their respective commands.
Evaluator adaptations belong in separate recorded work.

Original research checks remain available with
`python3 scripts/verify_research.py --research-root /path/to/colosseum`.
They verify pinned archived records, not current runtime execution. Historical replay
notes are [retained at the frozen revision](https://github.com/MihRazvan/cyperlink/blob/builder-exercise-v1/docs/local-replay.md).
The original research/fixtures are preserved read-only; current setup does not require
that checkout as an execution input.

## Comparison and open claims

The [source accounting](../evidence/2026-10-03/license-client-source-surface.json)
separates application adapters, reusable SDK, native proof tooling, authoring/deployment
and shared enforcement. The direct client independently handles its client instructions,
proof/context uploads, reconciliation and journal. It shares onchain programs, policy
compiler/circuit, native commitment bridge and provisioning with CyperLink.

Five decisions/two licenses, rollback/stale/replay, lost response and selected crash
recovery passed on both selected paths. No source-size ratio establishes productivity.
Full standalone upstream replacement, arbitrary failure-mode parity, external builder
effort, demand, retention, pricing and comparative advantage remain inconclusive.

Keep provisioning/proof, compile/upload, queue, callback, settlement and worker costs
separate. Recorded settlement CU/fees exclude the other stages; worker resources and
production throughput are not measured. Clean-machine installation, independent
operators and production/public-network qualification remain open.

The separate Permissions escrow demonstrates actual spending authority distinct from
owner-key autosigning. It does not establish private-query authorization or delegated
shared-policy execution. Host-controlled roles, malicious balance-cache recovery,
key loss and richer consumer rollback remain limits of that experiment.
